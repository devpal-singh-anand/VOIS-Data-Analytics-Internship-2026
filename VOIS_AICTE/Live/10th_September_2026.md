### Internship as experience

* Some companies count an internship as work experience and others do not. It is usually not treated as full-time experience.
* It gives a profile **preference during shortlisting** compared with profiles that have no internship.

### Academic credits

* Completing courses can earn academic credits.

## 9. Case Study — Food Delivery Analytics

A short case study showing how a data analytics problem is solved from start to finish. It was **not a new project**. It was an example of how the process works, and the notebook and dataset were shared on the Telegram group as a reference.

### Business context

Sales platforms such as Swiggy or Zomato store an entry for every delivered order. Common business problems are sales not growing, low profit in some areas and poor performance in some cities. The dataset lets these be investigated.

### The dataset

* Around **1,213 rows**
* Columns included order ID, order date, city, area, restaurant name, category, order value, quantity, discount, delivery fee, distance, delivery time, customer ID, customer rating, payment details, delivery status (delivered, cancelled or returned), weather, restaurant rating, delivery partner ID, profit, day and month.

### Workflow

1. **Understand the problem first.** In a real job the problem statement comes first and the data is collected to fit it.
2. **Set up Colab:** upload the data using the **file icon** in the left panel (Upload), instead of linking it through Google Drive. Then install and import the required libraries.
3. **Load and inspect the data:** head, shape and the data type of each column.
4. **Check the health of the data:** null values, duplicates and unique values.
5. **Clean the data.**
6. **Run statistics and draw graphs** to answer business questions.

```python
df.isnull().sum()          # null values per column
df.duplicated().sum()      # duplicate rows
df.drop_duplicates()       # remove duplicates
df['column'].unique()      # unique values in a column
```

*Illustrative snippet. The column names in the shared notebook may differ.*

### Data health findings

| Check | Finding |
| ----- | ------- |
| Null values | About 42 in the ratings column, 30 in weather, 25 in restaurant rating, and around 24 each in customer age and delivery time |
| Duplicates | Different from nulls. A null is an empty value, a duplicate is the same entry repeated. Duplicates should be found and deleted |
| Order status | Delivered or cancelled |
| Weather | Three values: summer, winter and rainy |
| Month | Six months of data |
| Day | Seven values. An eighth value would signal a mismatch in the data |
| City names | The same city appeared twice because of capital and small letters (for example Pune and Mumbai). This is fixed during cleaning |

Null values can be handled with statistical methods such as filling with the **median**.

### Business insights

* **Order value:** most orders fall between about ₹200 and ₹400. Adding food priced around ₹700 is unlikely to work, so pricing should stay close to this range.
* **Order status:** compare how many orders were delivered successfully against those cancelled.
* **Revenue by city:** find the strong cities (for example Pune, Mumbai and Nashik) and the weak ones (for example Nagpur), then investigate what is holding a weak city back.
* **Delivery time by city:** Mumbai is known for heavy traffic, which explains longer delivery times there. Graphs help spot this kind of pattern.
